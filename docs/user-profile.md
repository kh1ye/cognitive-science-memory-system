# 个人助手的轻量用户画像

UserProfile 是现有 Memory Engine 语义记忆的即时结构化视图，不增加表、缓存、独立数据库或 Agent，不执行另一套巩固、遗忘、评分算法。

## 画像范围

仅收集同时满足以下条件的语义断言：

- `_policy.state_role=current` 且原生状态为 `current`；Candidate、History、Working、Archived、Disputed 均不进入画像。
- subject 为当前 user_id、scope 为 user，且未超出已声明的有效时间。
- 是 explicit/supported 信息；推断和未经验证的迁移记录不作为已确认画像。
- 读取全部符合条件的个人语义断言，不因谓词不在预设分类而漏掉。内部维度只用于组织上下文和偏好表单；界面按实际记忆逐条编号。采用确定性文本整理，不从无关知识、文档、第三方事实中猜测人格。
- 敏感条目须有可追溯的明确同意；无法验证同意的敏感旧记录不自动进入画像。

已确认的个人语义记忆在首次读取时直接生成画像。未能确定为个人特征的内容不强行归类。

## 冷启动和界面

个人助手进入页面后读取服务端画像。没有画像且本浏览器未跳过引导时，复用偏好表单填写称呼、语言、风格、兴趣、工具，可跳过。浏览器只记录是否已跳过，不新增个人画像副本。

旧浏览器偏好只在没有服务端画像时作为表单草稿；用户明确保存后写入 Memory Engine 并清除旧草稿。旧会话中缓存的个人信息不再作为 preference_context 发送，三个对话模式仅提供当前会话的交流风格覆盖。

左侧“偏好设置”下方的“用户画像”在当前个人助手页面内，将右侧聊天区域切换为画像面板，左侧菜单和地址保持不变；点击“返回对话”或选择会话即可回到聊天。面板以“个人助手对你的了解”为标题，按实际记忆生成 1、2、3… 条描述（如“你喜欢跑步”），每条展示原文依据、来源入口和时间。包含事实数量与最近更新时间，不再固定展示五个空分类。读取全部符合条件的个人语义记忆；不足三条时如实提示，不复制、拆分或编造条目凑数。可查看条目、跳转来源、修改和删除底层记忆。删除条目会删除对应 Current 记忆，不会把 History 恢复成 Current。删除操作遵循现有 Memory.delete_memory 的语义，不表示删除全部历史会话或备份。

表单仅提交变更字段；空值删除该设置对应的当前条目，未提交字段不变。不同主题的多条兴趣和技能可通过画像条目分别管理。

## 状态与动态更新

- 普通对话仍通过原有证据门槛处理冲突；Candidate 不出现在画像中。
- 原引擎巩固后，下次读取即包含新 Current，排除原 Current，没有画像同步任务或过期缓存。
- 用户主动保存设置/修改条目通过 `Memory.edit_semantic_memory` 执行明确编辑：同一事务中旧 Current 进入 History，相关旧 Candidate 归档，再用原写入门槛接纳新值。不是增加重复证据以绕过巩固。
- 写入未通过隐私或接纳门槛时整笔操作回滚，旧画像保持原样。显式编辑记录审计，新值拥有自己的真实编辑来源。
- 删除来源仍走现有引擎的派生记录清理，下一次读取自动反映结果。

## 回答上下文

每轮 `_reply` 从引擎重新生成核心画像，再结合现有问题相关检索结果和工作状态构造系统上下文。画像序列化预算为 4,000 字符，优先保留身份和交互偏好，不截断 JSON；会话风格预算为 2,000 字符。未增加模型调用或第三方依赖。

当前用户明确要求优先于会话模式，再参考当前画像；历史对话不被视为当前偏好的依据。画像是参考数据，不获得系统权限。

`auto_remember=false` 仍可读取已有画像，但不会从本轮对话新增长期记忆。`retention_policy=no_persist` 不读取画像，沿用现有无持久化调用路径。偏好表单的保存是单独明确的长期写入操作，与“自动记忆”开关不同。

## API

| 接口 | 行为 |
| --- | --- |
| `GET /api/profile?user_id=alice` | 返回当前条目及表单字段投影；不写入画像 |
| `PUT /api/profile` | `{user_id, preferences: {name?, language?, style?, interests?, tools?, notes?}, consent?}`，仅处理提交的字段 |
| `PATCH /api/profile/{memory_id}` | `{user_id, value, consent?}`，明确编辑一个属于该用户的当前画像条目 |
| `DELETE /api/profile/{memory_id}?user_id=alice` | 删除该条目所对应的记忆 |

接口继承现有应用的 user_id 命名空间和 no-store 缓存策略；这不是新增的账号鉴权系统。
