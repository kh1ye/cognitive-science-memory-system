# 保持认知记忆定义的 Vatsalabench 优化对照

本次不改变工作、情景、语义、程序记忆定义，也没有修改 MEMORY_CONTENT_BOUNDARIES 或记忆概念分类提示。改变的是证据表示、索引、检索路由和记录报告的提取提示。

## 实现

1. 以BM25对内容字段和邻近来源证据排序，过滤零相关项，避免把JSON字段名、随机ID等持久化元数据当作正文。处理连字符和简单复数；没有加入样本专有实体、目标答案或题号分支。
2. 检索时附带最多3个来源、每处证据前后各400字符的原始上下文，恢复代词及对象指向；不把上下文另写成已证实语义事实。保留用户、作用域、时间、状态和来源删除边界。
3. 默认同时检索语义和情景记忆，各最多5条；工作记忆仍按任务隔离，程序记忆仍是可验证的执行能力，不把流程文字当成已安装能力。架构API默认检索范围与聊天对齐。
4. 对用户明确提供的相互矛盾资料，提取“收到这些记录”的情景报告并保留各来源原话、有效时间及明确给出的优先级，而不是将任一值强行升级为事实。已命名对象尽量作为语义subject。
5. 修复Windows下迁移备份连接未关闭造成的文件占用；对应测试夹具也显式关闭连接。

## 验证与限制

143项后端测试通过，覆盖来源上下文的作用域隔离、原始事实不变、空相关性、代词上下文、冲突报告不强行成为语义事实、SQLite副本隔离等。所有运行的12个检查点隔离验证通过；学习操作级失败为0，不等于提取完整。
这只是2条样本，每种方法单次运行；不是500条成绩或官方11指标综合分。验证样本本轮结果已查看，后续继续调试时不能再把它当全新盲测集。数据包审核标记仍待完成。
检索上限从仅语义5条扩为语义+情景最多10条，且附带上下文，输入token可能增加；comparison.json记录回答阶段用量和延迟，未完整采集提取成本。排序仍是词面方法，没有实现真正的跨语言语义向量检索。
没有改动现有用户数据库、没有重启正在运行的服务，也没有提交或推送Git。新代码通过新进程评测生效。
