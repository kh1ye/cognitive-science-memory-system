# 500条样本数据目录说明

## 一、最外层目录

| 文件或文件夹 | 用途 |
|---|---|
| `pending_umrr/` | 434条待完成拒认题内容复核的样本。待复核不等于不合格。 |
| `reviewed_umrr/` | 66条已有拒认题复核支持的样本。检查范围和深度不同，不代表11个指标全部最终审核通过。 |
| `index.json` | 500条样本的总目录，记录编号、原表顺序、样本路径和复核状态。路径以该文件所在目录为起点。 |
| `review_status.json` | 给程序读取的复核状态清单和数量统计。 |
| `REVIEW_STATUS.html` | 给人查看的状态清单。解压后用浏览器打开，可以筛选样本并进入对应文件。 |
| `README.md` | 原始交付说明，介绍使用方法、注意事项和实验环境要求。 |
| `provenance.json` | 来源与版本记录，用于追溯这一版数据如何整理而来。 |
| `checksums.json` | 文件校验值清单，用于检查文件是否损坏或被修改。 |
| `VALIDATION.json` | 完整交付包生成时的检查结果，证明当时文件复制和目录检查通过，不代表全部题目内容已最终审核通过。 |

本次未附带独立的 `review_records/` 文件夹。因此，README 中有关该目录的说明和清单中的部分 Review 链接，在本次发送版本中不可用。原有校验清单也没有因省略该目录而重新生成。

## 二、两个样本文件夹的内部结构

`pending_umrr` 和 `reviewed_umrr` 的内部组织方式相同：

```text
pending_umrr/ 或 reviewed_umrr/
└─ <sample_id>/                    一条样本的完整材料
   ├─ suite.json
   ├─ protocol.json
   ├─ answer_instruction.txt
   ├─ run_config.json
   ├─ adapter_config.json
   ├─ provider_config.json
   │
   ├─ samples/
   │  └─ <sample_id>/
   │     ├─ sample.json
   │     ├─ history.json
   │     ├─ probes.json
   │     └─ branches.json
   │
   └─ private/
      └─ <sample_id>/
         ├─ gold.json
         ├─ time_migration.json
         ├─ 部分样本特有的修订记录
         │
         └─ legacy_reference/
            ├─ gold.json
            ├─ absence_audit.json    部分样本有
            ├─ adopted_task.json    部分样本有
            └─ target_scan.json     部分样本有
```

`<sample_id>` 表示样本唯一编号，例如 `51a45a95`。同一个编号在不同层级重复出现，是组织结构的要求，不表示存在多条样本。


## 三、每条样本最外层的文件

### `suite.json`：样本入口

告诉实验程序本样本有哪些数据和配置文件，并保存公开输入文件的校验值。

它是“去哪里读取材料”的目录，不是历史对话，也不是标准答案。

### `protocol.json`：测试规则

规定实验如何进行，例如：

- 原始历史按什么顺序输入。
- 在哪些检查点提问。
- 如何进行延迟、信息更新和冲突测试。
- 如何隔离不同实验分支。
- 如何记录资源消耗和计算指标。

不同记忆系统进行对比时，应遵守一致的测试规则。

### `answer_instruction.txt`：统一回答要求

测试提问时使用的统一回答指令。不是标准答案，也不是某条历史消息。

### `run_config.json`：运行设置

记录运行哪个记忆系统、运行模式、并发数、重试设置，以及测试回答是否写回记忆等。

### `adapter_config.json`：记忆系统配置

当前主要是 MemoryBank 的配置，包括版本、检索方式、向量模型、记忆更新策略和遗忘设置等。

其中可能存在原电脑上的安装路径。换电脑或改用 Mem0 时，需要建立适配的新配置，不能直接照搬。

### `provider_config.json`：模型调用配置

记录模型服务地址、模型名称、温度、输出长度、超时等。

这不是存放 API 密钥的文件。完整运行环境和密钥需要另行准备。

## 四、`samples/` 下面是什么？

路径：

```text
<sample_id>/samples/<sample_id>/
```

这里是实际实验的数据材料。

| 文件 | 内容及用途 |
|---|---|
| `sample.json` | 样本基本信息，包括来源、编号、相关数据文件位置、时间参照和审查状态。 |
| `history.json` | 原始历史对话，包含会话、消息角色、内容和时间等。用于建立记忆，不应改写原始内容。 |
| `probes.json` | 测试问题、对应指标、实验分支和提问检查点。由程序在指定阶段提出，不应作为历史全部提前输入。 |
| `branches.json` | 为实验新增的会话，包含信息更新、不同类型冲突和延迟干扰等分支。各分支按协议分别执行，不应全部混成一段历史。 |

可以理解为：

- `history.json`：先让系统记住什么。
- `branches.json`：随后发生了哪些新情况。
- `probes.json`：在什么阶段问什么问题。
- `sample.json`：这条样本的身份和组织信息。

## 五、`private/` 下面是什么？

路径：

```text
<sample_id>/private/<sample_id>/
```

这里是评分、证据和处理记录。**整个 private 目录都不应输入被测记忆系统，也不能进入它的检索库。**

### `gold.json`：当前标准答案和评分依据

包含当前评分要求、预期答案、证据位置和相关注意事项。

评分应使用这一层的 `gold.json`，不要误用 `legacy_reference` 里面的旧版同名文件。

文件名叫“标准答案”不代表已经完成全部独立审核，仍需结合样本的复核状态判断。

### `time_migration.json`：时间规则处理记录

记录此前统一时间规则时的处理情况，例如：

- 原始问题时间和实验提问时间。
- 是否出现重复时间或时间倒序。
- 是否调整实验检查点或追加会话时间。
- 原始历史是否保持不变。
- 当时的校验和待审查状态。

它是处理过程记录，不是需要追加给模型的对话。

### 部分样本特有的修订记录

并非每条样本都有以下文件。缺少它们通常表示没有对应批次的修订，不表示样本缺失。

| 文件 | 用途 |
|---|---|
| `applied_temporal_revision.json` | 记录某一批已落实的时间相关修改，例如将问题中的时间参照表述得更明确。 |
| `applied_temporal_revision2.json` | 记录后续批次已落实的时间相关修改。 |
| `applied_content_revision3.json` | 记录已落实的内容或措辞修订，便于对照修改前后。 |
| `umrr_replacement_review4.json` | 记录特定拒认题的替换，包括旧题、新题、相关证据及替换理由。 |

这些文件用于追溯修改过程。运行和评分应读取当前的 `probes.json` 与当前 `gold.json`，不要把修改记录里的旧题再运行一遍。

## 六、`legacy_reference/` 里面是什么？

路径：

```text
<sample_id>/private/<sample_id>/legacy_reference/
```

这是最底层的历史参考目录，用于保留以前整理样本时的资料，不是当前实验的主入口。

| 文件 | 用途 |
|---|---|
| `gold.json` | 旧版标准答案和标注，用于对照追溯，不作为当前评分主文件。 |
| `absence_audit.json` | 拒认题的历史检索记录，包括检索词、扫描消息数量、命中内容等。检索不到答案不等于已经完成全历史语义复核。 |
| `adopted_task.json` | 从已复核表格采纳的问题和答案，以及来源行、单元格和在实验中的用途。 |
| `target_scan.json` | 围绕目标事实的检索结果，帮助定位相关会话与证据，不是最终复核结论。 |

这些参考资料可能与后来修改后的题目不完全一致，因此只用于理解来源和修改过程。

## 七、使用时最重要的区别

**测试输入与评分材料必须分开。**

- 历史输入：`history.json`。
- 按分支追加的实验输入：`branches.json`。
- 在指定检查点提出的问题：`probes.json`。
- 回答生成之后用于判分：当前 `private/<sample_id>/gold.json`。
- 修订记录和 `legacy_reference`：供研究人员追溯，不提供给被测系统。

这是一份数据和配置包，不是实验结果包，也不包含完整可运行环境。改用 Mem0 时，原则上保留历史、问题、分支和评分标准，另行开发接入代码及系统配置。
