# 遗忘功能演示样例

24 组明确标记的合成样例，时间跨度为 0–365 天，通过测试时钟模拟。41 份独立证据全部经过真实写入与重复强化流程，不直接修改稳定性、保持度或证据计数。

覆盖未确认记忆随时间衰减、相同经过时间下的重要性差异、2/4/7 份证据强化、长期记忆近期再确认、保护标签/高重要性/程序记忆保护，以及低价值工作层片段。

在项目根目录执行：

```sh
.venv/bin/python scripts/seed_retention_demo.py
.venv/bin/python -m unittest discover -s tests -p 'test_retention*.py' -v
```

进入 `/#/forgetting`，左下角切换用户空间为 `forgetting-demo` 查看。默认写入本地演示数据库；可用 `--db` 指定临时库。脚本只允许写入 `forgetting-demo` 或以 `forgetting-demo-` 开头的专用空间，重复执行不会刷新记忆时间、重复强化或恢复已归档记录。

2026-11-04 实测：`forgetting-demo` 保留 24 条归档前样例；另一个 `forgetting-demo-archive-test` 空间通过实际 HTTP 接口归档 11 条低价值记忆、保留 6 条保护记忆，全部正文及 41 份证据仍存在。关闭开关后归档数为零、检索衰减因子为 1；恢复开关后恢复时间降权。重复归档新增零条，其他用户表数据指纹一致，数据库完整性检查通过。

说明：归档使用 `write_score × R` 与阈值比较，因此低写入价值的工作片段即便保持度较高，也可以归档。保护记录的自然保持度可以很低，但不会被时间维护归档。
