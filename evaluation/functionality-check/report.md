## 需要修正的问题

### 1. 优先：演化/手动保存与助手读取不同记忆仓库

复现：在演化页面提交“我喜欢用 Python 写脚本。”，页面显示WRITE_CURRENT并返回记录；随后新建助手会话询问“我喜欢用什么编程语言写脚本？”，助手表示没有找到。

接口复核：旧`/api/search`能找到Python；新架构语义断言中没有Python。演化仍调用旧写入接口，聊天只检索新架构。这是当前兼容边界产生的实际功能断点。

代码入口：`api/routers/evolution.py:182`、`src/cognitive_memory/memory.py:68`、`src/conversation_agent/graph.py:192`。

### 2. 优先：总览与主记忆列表统计不包含新架构记录

复现：助手已保存2条语义断言和1条用户经历时，总览仍显示记忆总量0并提示空间为空；旧管理列表也显示0。四类面板能看到这些记录。随后演化向旧表新增1条，总览变成1，仍未计入新架构对象。

原因：总览和主列表使用旧表接口。四类面板说明了旧列表的兼容范围，但总览“你的记忆空间还是空的”仍容易让用户误以为数据没有保存。

代码入口：`api/routers/system.py:18`、`src/cognitive_memory/memory.py:215`、`frontend/src/composables/useWorkspace.js`。

### 3. 多项长期偏好在本次实测中漏提

输入“以后请用中文回复我。我平时最喜欢喝乌龙茶。”，预期形成语言偏好与饮品偏好。实际只保存乌龙茶，中文被放入本次工作约束。之后单独发送“以后默认用中文回复我”才形成语言断言。

这是一次真实模型提取遗漏，不意味着每次必然出现；说明多事实提取还需更严格的端到端检查。

### 4. 自动记忆关闭时，模型仍说“我记住了”

关闭自动记忆后发送“这是一条自动记忆关闭测试：我最喜欢的水果是杨桃。”。页面状态正确显示“自动记忆已关闭，本轮仅保留会话记录”，数据库也没有杨桃断言；但回复为“好的，我记住了：你最喜欢的水果是杨桃。”。

实际保存控制有效，回复承诺与真实回执不一致。应由实际保存结果决定确认文案，而不是让模型在写入前自行承诺。

### 5. 语义断言主体未可靠绑定当前用户

单独保存语言偏好时，断言subject实际为`user`，而非当前测试用户ID。该记录仍在正确的user_id命名空间内，但主体字段不一致，会影响实体匹配与后续更新。当前代码依赖提示要求模型使用真实ID，没有在候选校验中强制保证这一点。

## 附加观察

跨入口检索失败的那次模型回复包含两个Unicode替换字符，界面与保存的会话文本中均可见。尚未对比供应商原始响应，不能确定是在模型输出还是适配过程中产生。

本轮没有修改业务代码。前端执行了生产构建；新增文件为测试脚本、证据与报告。28项API测试的正文来源及派生知识已清理；内置程序元数据可能保留在随机隔离测试命名空间中。

本轮没有验证外部平台的真实部署、登录和官方运行环境，也没有用小样本功能检查重新估计模型通用分类准确率。
