## 问题 1：当前模型名称无效，聊天与模型提取被阻断

- 配置读取成功，提供方为 `anthropic`，模型名为 `MiniMax-M3[1m]`。
- 网页发送“我平时喜欢喝什么茶？请根据已有记忆回答。”后，`POST /api/chat` 返回 502，网页提示模型调用失败。
- 绕过记忆系统，用相同模型配置只发送一条连接测试，也得到提供方 HTTP 400：`invalid params, unknown model 'MiniMax-M3[1m]' (2013)`。这是已确认的服务端模型拒绝，不是检索不到。
- 演化页提交“我喜欢用 Python 写脚本。”同样返回 502，显示自动提取失败、本次未写入。
- 工作状态已实际取回乌龙茶记忆，但模型无法生成回答。因此真实聊天回答、模型自动学习、跨会话自然语言回答尚不能通过验收。
- 需要将模型名改为该服务实际支持的值，重启后复测。没有擅自选择替代模型或修改用户配置。

证据：[提供方错误记录](model-provider-evidence.json)、[网页错误截图](evolution-model-failure.png)。

## 问题 2：手动添加的记忆出现无效来源会话链接

复现：添加记忆 → 完整详情 → 来源证据 →“查看原始消息”。手动表单并没有聊天来源，但链接为 `#/assistant?thread=manual&message=...`，打开后提示“来源会话不可用：会话不存在”。

原因链：`storage/typed_records.py` 的 `source_from_evidence()` 将缺失会话填成 `manual`；`catalog.py` 的 `evidence()` 又将 `source_event_id` 当成 `message_id`；`SourceEvidence.vue` 只要看到 thread_id 就生成聊天链接。证据事件标识和真实聊天消息标识在这里混淆。

影响是来源跳转和展示，不影响本次手动记忆的正文保存及检索。修复应保留真实 thread/message 来源，没有聊天来源时只显示已知证据，不生成聊天链接。

证据：[来源 API 和评测任务结果](extra-evidence.json)、[来源跳转失败截图](manual-source-link.png)。
