# 统一150条测试集

[全部150条样例](cases.md)及[cases.json](cases.json)。四类各30条：复用原自然口语100条，并从此前32条补充集每类取5条；另加30条低价值输入。保留原始ID与冻结哈希，不删改旧争议标签。样本为作者标注，非独立标准基准。

最终结果：[逐条报告](results/20261028-095022/report.md)，分类119/120（99.17%）；低价值真实聊天过滤30/30，来源记录正文保留0条。全部API失败0。低价值修复前28/30和中间29/30的原始结果均保留。

低价值过滤操作：
1. Unicode NFKC、大小写和符号规范化后，完整匹配纯问候、确认、感谢、重复字符、测试/通信探测、纯算术提问；不按句长拒绝有意义事实。
2. 自动聊天入口对规则命中输入跳过长期候选提取，只生成正常答复。
3. 写入服务再强制降为no_long_term，外部分析器即使错误提出长期候选也不能保存。
4. 未命中规则且模型没有提取长期候选时，运行阶段也不保存来源正文，学习阶段不重复发起持久化观察；正文只在会话/任务状态。
5. 提取提示明确普通提问和试发消息不属于长期个人经历，不能把每次输入自动记为情景事件。

会话/任务状态仍持久化SQLite，尚无自动到期删除。手动保存走兼容接口，仍属于用户明确保存操作；规则未覆盖的复杂表达仍依赖模型，30/30不代表所有低价值输入都能过滤。

复现：.venv/bin/python evaluation/memory-150/run_eval.py；每次新建结果目录。--reuse-concepts仅用于过滤规则开发时复用已完成且不受影响的120条分类预测，路径会写入manifest。

回归：126项后端测试，125通过、1项外部运行时测试跳过。当前服务已重启；独立QA空间通过实际HTTP聊天接口复测通信探测、算术提问和未命中规则的问候，全部无长期写入、无来源正文。见 live-service-check.json。本轮代码与新测试集尚未提交/推送Git。
