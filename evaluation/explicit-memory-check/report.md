# 自动记忆的明确依据限制

问题：用户说“我喜欢早上跑步”时，曾同时保存晨跑偏好（explicit/current）和固定晨跑习惯（inferred/candidate），前端均笼统显示“已写入”。

## 修改

- 提取提示明确禁止从偏好推出频率、固定习惯或实际执行；多个明确事实仍可分别提取，不强制限制为一条。
- 用户观察的自动学习只接受 explicit 语义候选；在聊天源登记／学习前检查可写入候选，观察服务写入循环再次拦截 inferred、supported、legacy_unverified。仅有推断时只保留工作上下文，长期来源表不保存正文。
- 跳过候选仍使用原索引计算操作身份，重试不会把某个回执关联到另一条记忆。
- 成功的语义回执附带实际结果状态和认识状态；前端区分当前、候选、冲突、历史。旧回执没有这些字段时标明状态未记录，不推测其当时状态。
- 手动、带有效来源的底层断言管理接口不受自动提取限制影响。没有删除既有用户记忆或更改历史回执。

## 验证

- 后端133项测试：132通过，1跳过；前端52项通过，生产构建通过。
- 新增回归覆盖：偏好和推断同时产生且顺序变化时仅写偏好；只产生推断时保留工作上下文；直接观察 API 的拦截与重试；明确规律和两个不同事实不误拦；前端回执状态文案。
- 真实模型在独立测试空间的最终复测（live-results-v2.json）：

| 输入 | 结果 |
|---|---|
| 我喜欢早上跑步 | 1条当前明确语义偏好，无额外习惯候选 |
| 我每天早上跑步 | 1条当前明确规律晨跑记忆 |
| 我喜欢晨跑，也喜欢游泳 | 2条当前明确偏好，证据为原文连续片段 |

第一轮复测的并列偏好有一条证据片段不合法，记录在 live-results.json；补充提示说明省略主语不能补进原文证据后，最终复测通过。浏览器查看单条保存提示后恢复 demo-user。

## 适用范围

后端依赖提取结果的认识状态标注，且原文片段校验只能验证出处，不能独立证明任意自然语言断言成立。模型若误把推断标成 explicit，仍存在误写风险；本次不宣称消除了所有语义推断错误。
