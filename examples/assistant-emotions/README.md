# 情绪识别示例对话

从 2026-11-15 的 MiniMax-M3 真实模型检查中选取 6 组对话：

1. 开心的分享：😄
2. 疲惫时的简短回应：😴
3. 面试前的焦虑：😟
4. 反讽里的烦躁：😤
5. 他人的焦虑不是你的：😐
6. 情绪随对话变化：😔 → 😔 → 😌 → 😴

输入为人工编写的测试情境，回答保留真实模型输出。这些不是当前用户的经历或画像事实，回答也不是已经审定的知识；例如焦虑样例中存在“说三件事却列四项”的普通生成问题。

## 本地导入与 Git 同步

`conversations.json` 是可纳入 Git 的文本样例，不包含用户的真实数据库或密钥。Git 拉取代码后，在仓库根目录运行：

```sh
uv sync --locked
uv run python -m scripts.seed_emotion_conversations --user demo-user
```

建议停止后端后导入，再正常启动。默认写入 `memory_product/data/memory_demo_sessions.db`；可用 `--sessions-db` 指定其他会话库，也会读取 `CONVERSATION_DB_PATH` 环境变量。`--user` 对应个人助手中的用户空间。

刷新个人助手后，在最近会话中选择“开心的分享”“疲惫时的简短回应”等条目。聊天中不再插入测试说明消息；顶部表情状态显示该示例最后一轮的静态表情，例如开心 😄、疲惫 😴。这是示例回放标注，不是恢复用户当时的实时情绪。用户继续发送新消息后，立即改用实时自动识别，不再回退至旧示例表情。

导入不调用模型，不写入长期记忆，不改画像。相同 ID 已存在时保留原有对话；只移除旧版自动生成的测试提示消息，并为未被编辑的原始示例回复补齐静态表情标注，不覆盖用户的后续对话。完成迁移后再次运行将跳过，不重复添加消息。删除后不会自动重新出现，除非再次主动运行导入命令。现有用户会话保持原样。

真实运行数据库继续由 `.gitignore` 排除。需要同步的是本目录、导入脚本及测试，不是 SQLite 文件。

完整检查见 `evaluation/emotion-check-20261115/report.md`。固定输入和真实回答已复制到本目录的 JSON，导入无需依赖完整评测结果文件。
